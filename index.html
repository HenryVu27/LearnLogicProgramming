1. From Formal Logic to Logic Programming

Everything you know about formal logic maps directly to code.

The Key Mental Shift

In imperative programming, you tell the computer how to solve a problem (step-by-step instructions). In logic programming, you declare what is true and let the solver figure out the rest.

% Imperative (Python): HOW to check ancestry
% def is_ancestor(person, target, tree):
%     if person == target: return True
%     for child in tree[person]:
%         if is_ancestor(child, target, tree): ...

% Logic programming: WHAT is true about ancestry
parent(tom, bob).
parent(bob, ann).

ancestor(X, Y) :- parent(X, Y).
ancestor(X, Y) :- parent(X, Z), ancestor(Z, Y).

% Query: ?- ancestor(tom, ann).  --> true

You stated facts and rules. The solver derived the answer. No loops, no state management, no manual recursion handling.

The Direct Mapping

Here's how your formal logic knowledge translates to logic programming syntax:

Formal LogicLogic ProgrammingRead As
P(a) (ground fact) p(a). "a has property p"
∀x: P(x) → Q(x) q(X) :- p(X). "Q holds if P holds"
P(a) ∧ P(b) p(a). p(b). Two separate facts
∃x: P(x) ∧ Q(x) ?- p(X), q(X). Query: "find X where both hold"
¬P(x) not p(X) "P cannot be proven" (subtle!)
P(x) → ⊥ :- p(X). "P must never be true" (constraint)
A ∨ B {a ; b} = 1. "Exactly one of A or B" (ASP)

Syntax Rules

These apply across Prolog and ASP:

  • Constants (specific things) start lowercase: tom, adhd, homework
  • Variables (unknowns) start uppercase: X, Y, Person, Who
  • Facts end with a period: parent(tom, bob).
  • Rules use :- meaning "if": head :- body.
  • Comma means AND: a, b = "a and b"
  • Comments use %: % this is a comment
  • Underscore _ is an anonymous variable: "I don't care what this is"
% FACTS: unconditionally true
parent(tom, bob).          % Tom is Bob's parent
age(bob, 7).               % Bob is 7 years old
diagnosed(bob, adhd).      % Bob has ADHD

% RULES: conditional truths
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
% X is grandparent of Z IF X is parent of some Y AND Y is parent of Z

% QUERIES: what you want to know
% ?- grandparent(tom, Who).   "Who is Tom a grandparent of?"
% ?- parent(_, bob).          "Does Bob have a parent?" (don't care who)
Key Insight

The rule grandparent(X, Z) :- parent(X, Y), parent(Y, Z). is literally the formula ∀X,Y,Z: parent(X,Y) ∧ parent(Y,Z) → grandparent(X,Z) written in logic programming syntax. Your discrete math intuition applies directly.

Predicates: The Building Blocks

A predicate is a named relation with a fixed number of arguments (its arity):

  • parent(tom, bob) — predicate parent/2 (name/arity)
  • diagnosed(bob, adhd) — predicate diagnosed/2
  • happy(bob) — predicate happy/1

Predicates are the vocabulary of your logic program. In the FirstThen context, the LLM's job is to extract predicates from natural language: turning "My 7-year-old son Max has ADHD" into child_age(max, 7). diagnosed(max, adhd).

What does the rule needs_help(X) :- student(X), not passing(X). mean?

Correct! The not here is "negation as failure" — it means "we cannot prove passing(X) is true." This is the Closed World Assumption: if something isn't stated or derivable, it's assumed false.

2. Prolog Basics

The original logic programming language and foundation for s(CASP).

Why Learn Prolog?

Prolog (1972) matters because:

  1. s(CASP) runs inside SWI-Prolog and extends Prolog syntax
  2. ASP evolved as a response to Prolog's limitations (you need to understand both)
  3. The execution model (unification + backtracking) is the foundation of all logic programming

Unification: How Logic Programming "Computes"

Unification is the core mechanism. When Prolog tries to match a query against a rule, it unifies terms by finding variable bindings that make them identical:

% Can these unify?
parent(tom, X)   =   parent(tom, bob)
% YES: X = bob

parent(X, Y)     =   parent(tom, bob)
% YES: X = tom, Y = bob

parent(tom, bob)  =   parent(tom, ann)
% NO: bob ≠ ann

parent(X, X)     =   parent(tom, bob)
% NO: X can't be both tom and bob

parent(X, X)     =   parent(tom, tom)
% YES: X = tom
Think of it this way

Unification is like solving a system of equations. f(X, b) = f(a, Y) gives you X=a, Y=b. Prolog does this automatically, constantly, as its primary computation mechanism.

SLD Resolution: How Prolog Executes

When you query ?- ancestor(tom, ann)., Prolog performs top-down, depth-first search with backtracking:

parent(tom, bob).
parent(bob, ann).

ancestor(X, Y) :- parent(X, Y).                  % Rule 1
ancestor(X, Y) :- parent(X, Z), ancestor(Z, Y). % Rule 2
Query: ancestor(tom, ann) | +--> Try Rule 1: ancestor(X,Y) :- parent(X,Y) | Unify: X=tom, Y=ann | Need: parent(tom, ann) | FAIL (no such fact) | +--> Try Rule 2: ancestor(X,Y) :- parent(X,Z), ancestor(Z,Y) Unify: X=tom, Y=ann Need: parent(tom, Z) SUCCESS: Z=bob (from fact parent(tom,bob)) | Now need: ancestor(bob, ann) | +--> Try Rule 1: ancestor(X,Y) :- parent(X,Y) Unify: X=bob, Y=ann Need: parent(bob, ann) SUCCESS! (fact exists) RESULT: true

This is exactly like a proof search in natural deduction, but automated. Prolog tries rules top-to-bottom, goals left-to-right, and backtracks on failure.

Lists

Prolog lists are fundamental. They use [Head|Tail] pattern matching:

% List syntax
[1, 2, 3]              % A list of three elements
[a | [b, c]]          % Same as [a, b, c]
[H | T]                  % H = first element, T = rest of list
[]                       % Empty list

% Length of a list
len([], 0).
len([_|T], N) :- len(T, N1), N is N1 + 1.

% Member of a list
member(X, [X|_]).
member(X, [_|T]) :- member(X, T).

% Append two lists
append([], L, L).
append([H|T1], L2, [H|T3]) :- append(T1, L2, T3).

Notice how member/2 works: "X is a member of a list if X is the head, OR X is a member of the tail." Pure logic, no iteration.

Backtracking: Finding All Solutions

Prolog doesn't just find one answer — it can find all of them through backtracking:

likes(mary, pizza).
likes(mary, sushi).
likes(mary, tacos).

% Query: ?- likes(mary, What).
% Answer 1: What = pizza
% Answer 2: What = sushi  (backtrack, try next fact)
% Answer 3: What = tacos  (backtrack again)

Given parent(tom, bob). parent(tom, sue). parent(bob, ann)., what does ?- parent(tom, X). return?

Correct! Prolog finds X=bob first, and on backtracking finds X=sue. It does NOT find ann because parent(tom, ann) is not a fact.

3. Prolog Deep Dive

Arithmetic, negation, cut, and the limitations that led to ASP.

Arithmetic

Prolog treats everything as symbolic by default. For actual computation, you need is:

% WRONG: this tries to unify, not compute
% ?- X = 2 + 3.    --> X = 2+3  (a term, not 5!)

% RIGHT: use 'is' to evaluate arithmetic
% ?- X is 2 + 3.   --> X = 5

% Comparison operators
% ?- 5 > 3.        --> true
% ?- 5 =:= 2+3.   --> true (arithmetic equality)
% ?- 5 == 2+3.     --> false (structural equality)

% Factorial
factorial(0, 1).
factorial(N, F) :-
    N > 0,
    N1 is N - 1,
    factorial(N1, F1),
    F is N * F1.

Negation as Failure (NAF)

This is one of the most important concepts. Prolog's not (or \+) doesn't mean classical logical negation. It means "I cannot prove this":

bird(tweety).
bird(tux).
penguin(tux).

abnormal(X) :- penguin(X).
flies(X) :- bird(X), not abnormal(X).

% ?- flies(tweety).  --> true
%    (tweety is a bird, and we CAN'T prove tweety is abnormal)

% ?- flies(tux).     --> false
%    (tux is a bird, but we CAN prove tux is abnormal)
Closed World Assumption (CWA)

In logic programming, anything not stated or derivable is assumed false. If you don't say penguin(tweety)., then penguin(tweety) is false. This is different from classical logic where unknown things are simply unknown. The CWA is powerful for databases and chatbots: "If we haven't approved a topic, it's not approved."

Prolog's Limitations

These are the problems that motivated the creation of ASP:

1. Negation is order-dependent

% These two programs give different results in Prolog:

% Program A:
p :- not q.
q :- not p.
% Prolog tries p first, can't prove q, so p succeeds.
% But q :- not p would also be valid! There are TWO
% consistent worlds: {p} and {q}. Prolog only finds one.

2. No genuine disjunction

% "Go to the opera OR stay home" -- both valid
% Prolog can't naturally express this kind of choice.
% ASP can: { go_opera ; stay_home } = 1.

3. Infinite loops

p :- q.
q :- p.
% ?- p.  --> Prolog loops forever
% ASP handles this: neither p nor q is in the answer set

4. No multiple models

Prolog finds one answer path. But real problems often have multiple valid solutions (e.g., "which combination of strategies could work for this family?"). ASP computes all valid models.

Why this matters for FirstThen

A chatbot needs to handle ambiguity (multiple valid next steps), enforce hard constraints (safety bounds), and never loop. ASP was designed precisely for these requirements.

Practical Prolog Patterns

Despite its limitations, Prolog patterns appear constantly in s(CASP). Know these:

% Pattern 1: Accumulator (efficient recursion)
sum_list(List, Sum) :- sum_list(List, 0, Sum).
sum_list([], Acc, Acc).
sum_list([H|T], Acc, Sum) :-
    NewAcc is Acc + H,
    sum_list(T, NewAcc, Sum).

% Pattern 2: Generate and test
valid_pair(X, Y) :-
    candidate(X),       % generate
    candidate(Y),       % generate
    X \= Y,             % test
    compatible(X, Y).  % test

% Pattern 3: If-then-else via cuts (less common in ASP)
classify(Age, child)  :- Age < 12, !.
classify(Age, teen)   :- Age < 18, !.
classify(_, adult).

4. Why ASP Exists

From Prolog's limitations to a fundamentally different approach.

The Paradigm Shift

The key difference between Prolog and ASP:

Two Different Questions

Prolog asks: "Can I prove this specific query is true?" (top-down, one answer at a time)
ASP asks: "What are ALL consistent models where my rules hold?" (bottom-up, all answers at once)

What Is an Answer Set?

An answer set (also called a stable model) is a set of ground atoms that:

  1. Consistent — no contradictions
  2. Supported — every atom has a reason to be true (a rule that derives it)
  3. Minimal — nothing extra that isn't required

Think of each answer set as a "possible world" that satisfies all your rules and constraints.

% Simple program:
bird(tweety).
penguin(tux).
bird(tux).

abnormal(X) :- penguin(X).
flies(X) :- bird(X), not abnormal(X).

% The UNIQUE answer set:
% { bird(tweety), penguin(tux), bird(tux),
%   abnormal(tux), flies(tweety) }
%
% flies(tux) is NOT in the set.
% tux is abnormal, so "not abnormal(tux)" fails.

How ASP Solves Prolog's Problems

Problem 1: Multiple valid worlds

% Prolog: p :- not q. q :- not p.  --> only finds {p}

% ASP: Same program, finds BOTH answer sets:
p :- not q.
q :- not p.

% Answer set 1: { p }  (q is false, so "not q" holds, p derived)
% Answer set 2: { q }  (p is false, so "not p" holds, q derived)

Problem 2: Loops

p :- q.
q :- p.

% Prolog: infinite loop
% ASP: Answer set = {} (empty set)
% Neither p nor q has independent support, so neither is in any model.

Problem 3: Genuine choice

% "Choose to go to the opera or stay home"
{ go_opera ; stay_home } = 1.

% Answer set 1: { go_opera }
% Answer set 2: { stay_home }

% Both are valid. The solver enumerates all possibilities.

The Bottom-Up Approach

Traditional ASP solvers (like Clingo) work in two phases:

  1. Grounding: Replace all variables with concrete values to create a propositional program
  2. Solving: Use SAT-solver techniques to find all stable models
Program: Grounded: bird(tweety). bird(tweety). bird(tux). bird(tux). penguin(tux). penguin(tux). abnormal(X) :- penguin(X). --> abnormal(tweety) :- penguin(tweety). flies(X) :- bird(X), abnormal(tux) :- penguin(tux). not abnormal(X). flies(tweety) :- bird(tweety), not abnormal(tweety). flies(tux) :- bird(tux), not abnormal(tux). Then SAT-solve for stable models.

This grounding step is why traditional ASP can struggle with large domains. It's also why s(CASP) was invented (Chapter 7) — it skips grounding entirely.

Given the program a :- not b. b :- not a. c :- a., what are the answer sets?

Correct! In one world, a is true (because b can't be proven), and c follows from a. In the other world, b is true (because a can't be proven), and c has no support so it's excluded.

5. ASP Core Concepts

Choice rules, integrity constraints, optimization, and the patterns you need.

1. Choice Rules

Choice rules let you express nondeterministic decisions. The solver explores all valid combinations:

% "Exactly 1: the child is calm or agitated"
{ calm(C) ; agitated(C) } = 1 :- child(C).

% "Between 1 and 3 strategies from the set of all strategies"
1 { try(P, S) : strategy(S) } 3 :- parent(P).

% "At least 1 topic must be active"
1 { active_topic(T) : topic(T) }.

% "Maybe assign a strategy, maybe not" (0 or 1)
{ assign(S) } :- strategy(S).

The syntax L { atoms } U means "at least L, at most U of these atoms can be true." The colon : means "for each" (conditional set).

2. Integrity Constraints (Guardrails)

This is the most important ASP concept for FirstThen. Constraints are headless rules that eliminate invalid answer sets:

% Syntax: :- body.   "It is IMPOSSIBLE for this body to be true"

% Safety constraints for a healthcare chatbot:

% Never recommend medication
:- recommend(X), medication(X).

% Never provide a diagnosis
:- action(diagnose).

% Only discuss approved topics
:- discusses(T), not approved_topic(T).

% A child cannot be calm and in meltdown simultaneously
:- calm(C), meltdown(C).

% If crisis detected, MUST refer to professional
:- crisis_detected, not action(refer_professional).

% Every strategy session must include action steps
:- phase(strategy), not has_action_steps.
Why This Is Better Than Prompt Engineering

When you write :- recommend(X), medication(X)., any answer set that contains a medication recommendation is mathematically eliminated. The system cannot produce it. Period. Compare this to telling an LLM "don't recommend medications" in a prompt — which can be bypassed with jailbreaks. ASP constraints are formal guarantees, not suggestions.

3. Normal Rules

Standard rules for deriving new knowledge:

% Deriving strategy recommendations from challenges
suggest(visual_schedule) :- challenge(_, homework_avoidance).
suggest(first_then_board) :- challenge(_, homework_avoidance).
suggest(countdown)        :- challenge(_, bedtime_resistance).
suggest(calm_corner)      :- challenge(_, emotional_dysregulation).

% Don't suggest failed strategies
:- suggest(S), tried(_, S), outcome(S, negative).

% Conversation state transitions
intake_complete :-
    has_child_age,
    has_challenge,
    has_diagnosis.

current_phase(strategy) :- intake_complete.
current_phase(intake)   :- not intake_complete.

4. Show Directives

Control which atoms appear in the output:

% Only show suggestions and current phase
#show suggest/1.
#show current_phase/1.

% Without #show, Clingo outputs ALL atoms in the answer set.
% With #show, only the specified predicates appear.

5. Optimization

ASP can find optimal solutions, not just valid ones:

% Prefer strategies the family hasn't tried before
novel(S) :- suggest(S), not tried(_, S).

% Maximize novel suggestions
#maximize { 1,S : novel(S) }.

% Minimize overall number of suggestions (keep it focused)
#minimize { 1,S : suggest(S) }.

Complete Example: Strategy Recommender

% === DOMAIN KNOWLEDGE ===
strategy(visual_schedule). strategy(first_then). strategy(timer).
strategy(countdown). strategy(calm_corner). strategy(token_reward).

for_challenge(visual_schedule, homework).
for_challenge(first_then, homework).
for_challenge(timer, homework).
for_challenge(countdown, transitions).
for_challenge(calm_corner, meltdowns).
for_challenge(token_reward, homework).
for_challenge(token_reward, transitions).

% === FAMILY CONTEXT (from predicate extraction) ===
child(max). child_age(max, 7). diagnosed(max, adhd).
challenge(max, homework).
tried(max, timer). outcome(timer, negative).

% === RECOMMENDATION LOGIC ===
applicable(S) :- strategy(S), challenge(_, C), for_challenge(S, C).
blocked(S)     :- tried(_, S), outcome(S, negative).

% === SAFETY ===

% Output: recommend(visual_schedule) recommend(first_then)
%         recommend(token_reward)
% Note: timer is NOT recommended (tried, negative outcome)

What does :- phase(strategy), not has_action_steps. mean?

Correct! Integrity constraints eliminate answer sets where their body is true. This guarantees that any valid answer set in the strategy phase MUST include action steps.

6. ASP in Practice (Clingo)

Writing and running real ASP programs with the Clingo solver.

Clingo: The Standard ASP Solver

Clingo is from the Potassco project (University of Potsdam). It's the most widely used ASP solver. You write .lp files and run them:

% Install: pip install clingo
% Or download from https://potassco.org/clingo/

% Run: clingo program.lp
% Run with N answer sets: clingo program.lp N
% Run all answer sets: clingo program.lp 0

Program Structure

A typical Clingo program has three parts: Generate, Define, Test:

% ---- GENERATE: what choices exist ----
1 { assign(Child, Strategy) : strategy(Strategy) } 3
    :- child(Child).

% ---- DEFINE: derive additional knowledge ----
has_strategy(C) :- assign(C, _).
novel(C, S) :- assign(C, S), not tried(C, S).

% ---- TEST: eliminate invalid combinations ----
:- assign(C, S), contraindicated(C, S).
:- child(C), not has_strategy(C).

#show assign/2.

Encoding Patterns

Pattern 1: State Machine (Conversation Phases)

% Phases
phase(intake). phase(strategy). phase(progress). phase(followup).

% Exactly one phase active
1 { current(P) : phase(P) } 1.

% Transition rules (constraints on which phase can be active)
:- current(strategy), not intake_done.
:- current(progress), not strategy_selected.

% Intake is done when all required info gathered
intake_done :- has_age, has_challenge, has_diagnosis.

Pattern 2: Classification / Matching

% Map behaviors to topics
maps_to(distraction, homework).
maps_to(avoidance, homework).
maps_to(meltdown, emotional_regulation).
maps_to(tantrums, emotional_regulation).
maps_to(wont_stop, transitions).

% Determine relevant topic from extracted behavior
relevant_topic(T) :- behavior(B), maps_to(B, T).

% Get strategies for relevant topics
applicable(S) :- relevant_topic(T), strategy_for(T, S).

Pattern 3: Default Reasoning

% Default: topics are approved unless explicitly blocked
approved(T) :- topic(T), not blocked(T).

% These are explicitly blocked
blocked(medication).
blocked(diagnosis).
blocked(legal_advice).

% Everything not blocked is approved by default.
% This is the Closed World Assumption at work.

Running Clingo from Python

import clingo

def solve(program_text):
    ctl = clingo.Control()
    ctl.add("base", [], program_text)
    ctl.ground([("base", [])])

    solutions = []
    with ctl.solve(yield_=True) as handle:
        for model in handle:
            solutions.append([str(atom) for atom in model.symbols(shown=True)])
    return solutions

program = """
child(max). child_age(max, 7). diagnosed(max, adhd).
challenge(max, homework).

strategy(visual_schedule). strategy(first_then). strategy(timer).
for_challenge(visual_schedule, homework).
for_challenge(first_then, homework).
for_challenge(timer, homework).

tried(max, timer). outcome(timer, negative).

applicable(S) :- strategy(S), challenge(_, C), for_challenge(S, C).
blocked(S) :- tried(_, S), outcome(S, negative).
recommend(S) :- applicable(S), not blocked(S).

:- recommend(S), medication(S).

#show recommend/1.
"""

results = solve(program)
for ans in results:
    print("Answer set:", ans)
# Output: Answer set: ['recommend(visual_schedule)', 'recommend(first_then)']

7. s(CASP): Goal-Directed ASP

Gopal Gupta's innovation — the actual technology behind FirstThen.

Why s(CASP)?

Remember: traditional ASP (Clingo) grounds the entire program before solving. s(CASP) takes a fundamentally different approach:

FeatureClingo (traditional ASP)s(CASP)
ExecutionBottom-up, SAT-solver basedTop-down, goal-directed (like Prolog)
GroundingMust ground all variables firstNo grounding needed
VariablesMust be ground before solvingRetains logical variables
Infinite domainsCannot handleHandles naturally (via constraints)
ExplainabilityAnswer sets onlyJustification trees
SemanticsStable modelStable model (same!)
SpeedFast for finite, ground problems~8ms per query (goal-directed)
The Best of Both Worlds

s(CASP) = ASP semantics (stable models, integrity constraints, proper negation) + Prolog execution (top-down, goal-directed, only computes what's needed). It gives you ASP's logical guarantees with Prolog's efficiency.

s(CASP) Syntax

s(CASP) runs inside SWI-Prolog. The syntax is very close to Prolog with ASP extensions:

:- use_module(library(scasp)).

% Facts and rules look like Prolog
parent(tom, bob).
parent(bob, ann).
ancestor(X, Y) :- parent(X, Y).
ancestor(X, Y) :- parent(X, Z), ancestor(Z, Y).

% Negation as Failure works like ASP (stable model semantics)
flies(X) :- bird(X), not abnormal(X).
abnormal(X) :- penguin(X).

% Queries use scasp/2
% ?- scasp(flies(tweety), []).

Two Kinds of Negation

This is critical. s(CASP) supports both:

Negation as Failure: not p

"I cannot prove p, so I assume it's false." (Closed World Assumption)

% "A topic is safe unless explicitly flagged"
safe_topic(T) :- topic(T), not flagged(T).
% If nothing says T is flagged, then it's safe by default.

Classical (Strong) Negation: -p

"p is explicitly false." A positive assertion of falsehood.

% "Penguins explicitly do NOT fly"
-flies(penguin).

% "We explicitly do NOT provide medication advice"
-provides(medication_advice).

% Innocent until proven guilty:

A5 Nth Element of a List

A6 Backtracking Through a Family Tree

Given the following program and query, what results does Prolog return (in order)?

parent(tom, bob).
parent(tom, liz).
parent(bob, ann).
parent(bob, pat).

ancestor(X, Y) :- parent(X, Y).
ancestor(X, Y) :- parent(X, Z), ancestor(Z, Y).

X = liz ;
X = ann ;

Prolog tries the first ancestor clause, which directly matches parent(tom, X). This gives X = bob first (the first parent fact), then X = liz on backtracking. The key insight is Prolog uses depth-first search, exploring each branch fully before backtracking.

C5. What is the difference between not p and -p in ASP?

Correct: B. These are fundamentally different. not p (negation as failure / default negation) means "there is no evidence that p is true" — it succeeds when p cannot be derived. -p (strong/classical negation) means "p is explicitly known to be false" — it requires a rule or fact that derives -p. The distinction matters: in an open world, not p may hold (no info about p) while -p does not (nobody said p is false). ASP supports both, enabling nuanced reasoning about the difference between "unknown" and "known false."

C6 What's the Output — Two Kinds of Negation (Trace)

Given the following ASP program that uses both default negation (not) and classical negation (-), determine the answer sets:

-p :- not p.
q :- p, not r.
r :- -p.

How many answer sets are there? What are they?

There are 2 answer sets:

% Answer Set 1: { p, q }
% Answer Set 2: { -p, r }

Trace for Answer Set 1: { p, q }

  • Assume p is true.
  • Rule 1: p :- not -p. — Is -p derivable? No (we have p, not -p). So not -p holds. p is supported.
  • Rule 2: -p :- not p. — Is p derivable? Yes. So not p fails. -p is not derived.
  • Rule 3: q :- p, not r. — p is true. Is r derivable? r needs -p, which is not derived. So not r holds. q is derived.
  • Rule 4: r :- -p. — -p is not true. r is not derived.
  • Stable check passes: { p, q } is an answer set.

Trace for Answer Set 2: { -p, r }

  • Assume -p is true (p is explicitly false).
  • Rule 2: -p :- not p. — Is p derivable? No. So not p holds. -p is supported.
  • Rule 1: p :- not -p. — Is -p derivable? Yes. So not -p fails. p is not derived.
  • Rule 4: r :- -p. — -p is true. r is derived.
  • Rule 3: q :- p, not r. — p is not true. q is not derived.
  • Stable check passes: { -p, r } is an answer set.

Key insight: This program demonstrates how the two negations interact. In Answer Set 1, p is true by default (we can't prove -p), and q follows. In Answer Set 2, p is explicitly false, so r is derived instead. Notice that p and -p cannot both be in the same answer set (that would be a contradiction), so we get two consistent worlds.

C8. In s(CASP), what is a justification tree?

Correct: B. A justification tree is one of s(CASP)'s most powerful features. When s(CASP) proves a query, it can generate a tree-structured explanation showing: (1) which rules were used, (2) which subgoals were proven and how, (3) why negation-as-failure goals succeeded (i.e., what was searched for and not found). This makes s(CASP) outputs explainable — critical in domains like healthcare where you need to justify why a chatbot gave a particular recommendation. The justification tree can even be rendered in natural language using s(CASP)'s built-in translation capabilities.

C9. What is the key difference between s(CASP) and Clingo?

Correct: B. This is the fundamental architectural difference. Clingo (the most popular ASP solver) uses a ground-and-solve approach: it first instantiates all rules with all possible constants (grounding), then uses a SAT-like solver to find answer sets. s(CASP) takes a goal-directed, top-down approach like Prolog: given a query, it works backward through rules to prove it, without needing to ground the entire program. This means s(CASP) can handle programs with infinite domains (e.g., integers), produce justification trees for individual queries, and work incrementally — all advantages that make it well-suited for conversational AI where you query specific things rather than computing all possible answer sets.

D4 Safety Integrity Constraints for ADHD Chatbot

The constraints must enforce: (1) no medication discussion, (2) no diagnosis, (3) crisis triggers referral, (4) only approved strategies, (5) max 3 recommendations per session. % Write 5+ integrity constraints that make the ASP solver
% reject any answer set violating clinical safety rules.
% ========================================
% Safety Integrity Constraints
% ========================================

% 1. NEVER discuss medication
%    If any response predicate references medication, reject.
:- response_topic(medication).
:- response_contains(dosage).
:- response_contains(prescription).

% 2. NEVER provide a diagnosis
%    The chatbot coaches behavior strategies, not clinical diagnoses.
:- response_topic(diagnosis).
:- response_contains(diagnose).
:- suggest(clinical_assessment).

% 3. Crisis indicators MUST trigger professional referral
%    If a crisis is detected, the only valid action is referral.
:- crisis_detected, not refer_to_professional.
:- crisis_detected, recommend(_).

% 4. ONLY recommend clinician-approved strategies
%    Any recommendation not in the approved list is rejected.
:- recommend(S), not clinician_approved(S).

% 5. Maximum 3 recommendations per session
%    Overwhelming parents with too many strategies is counterproductive.
too_many_recs :- #count{ S : recommend(S) } > 3.
:- too_many_recs.

% 6. Do not recommend strategies already tried and failed
%    Respects the parent's experience.
:- recommend(S), tried_strategy(_, S), outcome(S, ineffective).

% 7. Require at least one recommendation when a challenge exists
%    Don't leave parents without guidance.
:- challenge(_, _), not crisis_detected, #count{ S : recommend(S) } = 0.

Integrity constraints are the cornerstone of ASP-based safety. Unlike prompt-based guardrails, these are mathematical guarantees: the ASP solver will produce no answer set at all if any constraint is violated. There is no way to "jailbreak" an integrity constraint — it is enforced at the solver level, not by an LLM. Constraint 3 is particularly important: if crisis indicators are extracted from the parent's message, the only permissible action is referral. The solver cannot produce a plan that both detects a crisis and recommends a behavioral strategy. Constraint 5 uses an aggregate #count to limit the number of concurrent recommendations, preventing information overload for already-stressed parents.

D5. Why can't prompt engineering alone provide the same safety guarantees as ASP integrity constraints?

B is correct. This is the fundamental insight behind the STAR architecture. Prompt engineering (e.g., "You must never discuss medication") is a soft constraint — it works most of the time but can fail due to prompt injection, adversarial inputs, context window overflow, or simply stochastic LLM behavior. ASP integrity constraints like :- response_topic(medication). are hard constraints enforced by the solver: if any answer set contains response_topic(medication), that answer set is discarded entirely. There is no input a user can provide that bypasses solver-level enforcement. This is why healthcare applications need symbolic reasoning in the loop — probabilistic safety is not sufficient when patient wellbeing is at stake.

D9. What is a Conversational Knowledge Template (CKT)?

B is correct. Unlike a prompt template (A), CKTs don't contain natural language — they are logical rules. Unlike a database schema (C), they encode reasoning about dialog flow. The LLM generates the actual natural language questions, but the CKT decides which question to ask. D15. Why is s(CASP) preferred over Clingo for the chatbot reasoning engine?

B is correct. s(CASP), developed by Gopal Gupta's group at UT Dallas, has three key advantages for conversational AI. First, it is goal-directed: instead of computing all possible answer sets (like Clingo's ground-and-solve approach), it only explores the portion of the program relevant to the specific query, making it efficient for large knowledge bases. Second, it produces justification trees that explain why a conclusion was reached in human-readable form — essential for healthcare applications where clinicians need to audit the chatbot's reasoning. Third, it works without grounding (expanding all possible variable bindings), which means it can handle programs with infinite domains or large variable spaces. Clingo (C) does support negation-as-failure, so that option is incorrect.

D16 Off-Topic and Unknown Behavior Handling

Write ASP rules for handling off-topic inputs. When the LLM extracts a behavior not in the known mappings, the system should: (a) detect it's off-topic, (b) suggest redirecting to the closest approved topic, (c) if no behavior was extracted at all, ask for clarification.

% The system needs to gracefully handle these cases
% without giving inappropriate advice.
% ========================================
% Off-Topic and Unknown Input Handling
% ========================================

% Known behavior categories (the system's scope)
known_behavior(homework_refusal).
known_behavior(morning_routine).
known_behavior(emotional_outburst).
known_behavior(task_transition).
known_behavior(bedtime_resistance).
known_behavior(social_conflict).
known_behavior(impulse_control).

% Behavior similarity mappings (for redirection suggestions)
% Format: similar_to(UnknownBehavior, KnownBehavior)
similar_to(school_refusal, morning_routine).
similar_to(tantrum, emotional_outburst).
similar_to(meltdown, emotional_outburst).
similar_to(wont_listen, impulse_control).
similar_to(fighting_siblings, social_conflict).
similar_to(screen_time_battle, task_transition).
similar_to(wont_eat, task_transition).
similar_to(chore_refusal, homework_refusal).

% ---- Detection Rules ----

% Case 1: Behavior extracted but not in known set
off_topic(Ch) :-
    challenge(_, Ch),
    not known_behavior(Ch).

% Case 2: No behavior extracted at all
no_behavior_extracted :-
    not has_any_challenge.

has_any_challenge :- challenge(_, _).

% ---- Response Rules ----

% If off-topic but we have a similar known behavior, redirect
redirect_to(KnownBh) :-
    off_topic(Ch),
    similar_to(Ch, KnownBh).

% If off-topic with no similar mapping, suggest general topics
suggest_topic_list :-
    off_topic(Ch),
    not has_redirect(Ch).

has_redirect(Ch) :-
    off_topic(Ch),
    similar_to(Ch, _).

% If nothing extracted, ask for clarification
ask_clarification :-
    no_behavior_extracted.

% ---- Response Mode ----
response_mode(redirect) :- redirect_to(_).
response_mode(suggest_topics) :- suggest_topic_list.
response_mode(clarify) :- ask_clarification.
response_mode(normal) :-
    has_any_challenge,
    not off_topic_exists.

off_topic_exists :- off_topic(_).

% ---- Integrity Constraints ----

% Cannot recommend strategies for off-topic behaviors
:- recommend(_), off_topic_exists.

% Cannot recommend when no behavior identified
:- recommend(_), no_behavior_extracted.

% Must have exactly one response mode
:- not response_mode(_).

#show response_mode/1.
#show redirect_to/1.
#show suggest_topic_list/0.
#show ask_clarification/0.

This system handles three out-of-scope scenarios. (1) Redirectable: the parent mentions something outside the exact vocabulary but close to a known behavior (e.g., "tantrums" redirects to emotional_outburst). The LLM can then say: "It sounds like you're describing emotional outbursts — I can help with that!" (2) Fully off-topic: the behavior has no similar mapping (e.g., the parent asks about medication). The system presents available topics. (3) Nothing extracted: the message was too vague or unrelated. The system asks for clarification. Critically, the integrity constraints ensure that no coaching recommendations are made in any off-topic scenario — the system stays in its lane.

11. Interview Prep

Key concepts, expected questions, and how to talk about this architecture.

Concepts You Must Be Able to Explain

1. "Why use ASP instead of just prompt engineering the LLM?"

Your Answer Framework

Prompt engineering provides suggestions to the LLM. ASP provides mathematical guarantees. When you write :- recommend(X), medication(X)., the system literally cannot produce a medication recommendation. No jailbreak, no prompt injection, no edge case can override it. For a healthcare product, especially one targeting children with ADHD, you need guarantees, not suggestions. Additionally, ASP gives you justification trees for regulatory compliance, declarative rule updates when clinical guidelines change, and consistent behavior that doesn't drift with model updates.

2. "How does predicate extraction work?"

The LLM is given a constrained vocabulary of predicates (defined by the domain). It acts as a structured information extractor, mapping natural language to these predicates. The vocabulary maps directly to the ASP program's expected inputs. The LLM cannot invent new predicates — only extract from the approved set. Multi-stage extraction (LLM extracts, ASP validates) improves accuracy from ~74% to ~81% F1.

3. "What is s(CASP) and how does it differ from regular ASP?"

s(CASP) is a goal-directed ASP implementation by Dr. Gopal Gupta. Unlike Clingo (bottom-up, requires grounding), s(CASP) works top-down like Prolog but with stable model semantics. Key advantages: no grounding (handles infinite domains), retains variables, produces justification trees (explainability), and runs in ~8ms per query. It gives you ASP's logical guarantees with Prolog's execution efficiency.

4. "How do clinician-defined bounds work technically?"

Clinicians define rules and constraints in ASP:

  • Approved topics: Facts like approved_topic(behavioral_strategies).
  • Safety constraints: Rules like :- discusses(T), not approved_topic(T).
  • Strategy mappings: Rules connecting challenges to evidence-based strategies
  • Conversation flow: CKTs (Conversational Knowledge Templates) defining what to ask and when

When guidelines change, clinicians update the ASP rules. No model retraining needed.

5. "How do you prevent LLM hallucination?"

The LLM never makes decisions. It's a translator (NL → predicates, predicates → NL). All reasoning happens in ASP, which is deterministic and formally verifiable. Even if the LLM extracts incorrect predicates, the ASP constraints catch unsafe combinations. The system has multiple defense layers: constrained extraction vocabulary, ASP validation, integrity constraints, and justification trees for audit.
